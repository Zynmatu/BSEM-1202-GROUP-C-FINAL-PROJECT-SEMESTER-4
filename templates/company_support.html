About Us
Built for modern HR teams
Apex Corp HR is a purpose-built Human Resource Management platform offering a fully async, production-grade REST API for managing the complete employee lifecycle — from onboarding to payroll.
🔐

Enterprise Security

OAuth2 + JWT authentication with bcrypt password hashing, role-based access control, and token refresh flows out of the box.

⚡

Fully Async

Built on FastAPI with asyncpg and SQLAlchemy async — handles thousands of concurrent requests without blocking the event loop.

🗄️

PostgreSQL Native

Structured relational data with full ORM support, cascading deletes, indexed queries, and Alembic migration support.

📖

Self-Documenting

Auto-generated OpenAPI schema with custom branded ReDoc and Swagger UI — always in sync with your live endpoints.

🏖️

Leave Management

Submit, review, approve and audit leave requests — annual, sick, maternity/paternity, and emergency leave types supported.

💰

Payroll Engine

Automated net-pay calculations with configurable bonuses and deductions per pay period; full audit trail included.

FAQ
Frequently Asked Questions
Common questions about integrating with and using the HR Management API.
How do I authenticate with the API? ▼
Use the OAuth2 password flow at POST /auth/token with your username (email) and password. The response includes an access_token (30 min) and a refresh_token (7 days). Pass the access token in all subsequent requests as Authorization: Bearer <token>. When the access token expires, call POST /auth/refresh with the refresh token to get a new pair.
What roles are available and what can each do? ▼
There are four roles: admin (full access, user management, delete operations), hr_manager (read + write employees, payroll, leave — no user deletion), employee (read own profile, submit leave requests), and readonly (read-only access to non-sensitive endpoints). Assign roles during user creation or update them via PATCH /users/{id} — only admins can change roles.
How do I create an employee? ▼
First create a user account via POST /auth/register or POST /users/ (admin only). Note the returned id. Then call POST /employees/ with user_id, first_name, last_name, and hire_date. An employee_number is auto-generated (e.g. EMP-000001) if you don't supply one. You can optionally assign department_id and role_id at creation or update them later.
How does pagination work? ▼
List endpoints like GET /employees/ and GET /users/ support ?page=1&per_page=20 query parameters (default 20 per page, max 100). The response includes a meta object with total, page, per_page, and pages fields so you can build paginated UIs easily.
What is the async employee enrichment endpoint? ▼
GET /employees/{id}/enrich demonstrates async I/O concurrency. It fetches the employee from the database and simultaneously fires two external HTTP calls using asyncio.gather(), which runs both tasks concurrently rather than sequentially — cutting total wait time. This pattern is the recommended approach for any endpoint that needs to fan out to multiple services.
How do I set up the database locally? ▼
Install PostgreSQL and create a database and user matching your .env file values. Copy .env.example to .env and fill in DATABASE_URL and SYNC_DATABASE_URL. Run uvicorn main:app --reload — the app calls init_db() on startup which auto-creates all tables. For production, use Alembic migrations instead of init_db().
Where is the interactive API documentation? ▼
Three documentation interfaces are available: the custom branded ReDoc at /redoc (also at /docs/hr) with HR-specific theming and response grouping; the standard Swagger UI at /docs which lets you try endpoints directly in the browser; and the raw OpenAPI JSON schema at /openapi.json for programmatic consumption or import into tools like Postman or Insomnia.
